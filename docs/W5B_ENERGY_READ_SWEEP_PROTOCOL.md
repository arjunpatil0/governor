# Protocol (NOT RUN, not tonight): NVML energy-counter phantom energy per read versus GPU state (written 2026-10-24; a side finding for the paper, outside the confirmatory reading)
Question: how many joules does one extra nvmlDeviceGetTotalEnergyConsumption read add, and how does that depend on the GPU state? Known: journal 0005 about 4.2 J (one state); diagnostic of 2026-10-24: 7.5 J per read with the g'B static state (3B, S1, locked 1800 MHz) and 2.7 J per read with the c'B state (addendum O-5).
Design: three fixed states, each a static cell of the existing hardware executor (no controller): (A) the g'B action 1800_a_g0_d1, 3B, S1, c0 = 7; (B) arm a (unlocked, unaligned duty 1), 3B, S1 (heavy load); (C) foreground alone at a locked 1800 MHz, no background (light load); optionally (D) GPU idle with a CUDA context. For each state, energy-read rate r in {0 (the start/end pair only), 1, 2, 5, 10, 20} Hz from a separate reader thread, 60 s measured + 5 s warm-up per cell, 3 repeats, run in a seeded random order, 20 s cool-down. Per cell log: counter power E (start/end pair, so the reader's reads are the only extra), sampled mean M (250 Hz GetPowerUsage; the reader does not touch it), the achieved reads/s, tok/s, temperature.
Outcome per state: the slope of (E - M) in W against r in reads/s = J per read, with a 95% CI from the repeats; the intercept (r = 0) = the state-dependent offset of the counter vs the sample mean. Checks: M must be independent of r (within 3%); tok/s independent of r (the reads cost the workload nothing); if M changes with r the reader disturbs the GPU and the slope is not a counter effect.
Reading: descriptive. No hypothesis about the study depends on it (the study never reads the counter in a loop); the result goes to docs/PAPER_MAP.md as a measured side finding and explains the 2.7-7.5 J spread.
Implementation (when approved): `tune.py --sweep` with a reader thread; test-first on a fake counter whose phantom is known; the existing tooling (telemetry/power_energy_diagnostic.py, experiment B) is the starting point.
