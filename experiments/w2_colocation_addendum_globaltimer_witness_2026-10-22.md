## Finding that motivates it (smoke-grade: unlocked clocks, one block; reproducible in a minute)
With NO other process, the instrumented fma kernel at the harness grid (6 blocks per SM) shows logged gaps of about 260 us in a fixed share of its blocks. Controlled sweep of blocks per SM, bg kernel alone, 1.5 s each: 1, 2, 3 blocks/SM: 0 blocks with a gap >= G_thr; 4: 25%; 5: 40%; 6: 50% (the blocks beyond the first three per SM). In g_bgalone exactly 132,192 of 264,384 recorded blocks (50.0%) have a gap >= G_thr, median 267 us. A block-level gap therefore does not by itself mean the context was switched out: blocks beyond the first three per SM are starved by the SM's warp arbitration while the earlier blocks run. Blocks 0-107 had no gaps alone in every cell inspected.

## A. Witness blocks (replace "all trusted blocks" in addendum 2 sections A-C)
- Every block is still recorded and the gap logs are kept. ALL block-level analyses use WITNESS blocks only, for the foreground and the background alike: launch ON-sets and runs, q, s, OVERLAP (P6), the PREEMPTED fraction (P7), G_thr, and the alone spans used for the sliced-span test. P6 OVERLAP compares witness-fg on-intervals with witness-bg on-intervals only. An fg block "executing" means its on-intervals = its span minus its own logged gaps, as in addendum 2 section B (gaps longer than the 20 us logging threshold; G_thr, about 25 us on witness blocks, defines only the P7 "preempted" test).
- The witness set is VERIFIED, not assumed. Nominal witnesses: blockIdx < 108 (3 x 36). For every launch the recorded %smid is checked: every SM must host exactly 3 nominal witnesses. A launch that passes uses the nominal set. A launch that fails uses the data-driven rule, fixed now: the 3 earliest-starting blocks on each SM (ties broken by blockIdx); a launch in which any SM hosts fewer than 3 blocks is excluded. Per cell the report states the number of launches that passed, used the fallback, and were excluded.
- Validity gate, evaluated and printed per run: (i) in g_bgalone the witness blocks' preempted fraction (gap >= G_thr) must be below 1%; (ii) the placement check above. If the gate fails, P6, P7, q and s are reported but NOT interpreted.
- The all-blocks view is also reported, labelled SECONDARY, with the arbitration artefact stated next to it. Report P6 and P7 per m with their recorded-interval coverage.

## B. Control cells: arbitration-free 3 blocks per SM (+2 cells; 17 per block, 170 cells)
- g_T4_3bpsm: the T4 cell (fg 4 ms Poisson 40 Hz, 400 requests; bg slice m = 2 ms, constant, duty 1) with BOTH the fg and the bg kernel launched at 3 blocks per SM (108 blocks of 256 threads; every block is a witness; the sweep shows no arbitration gaps there). Instrumented. The grid change needs its own calibration (3-blocks-per-SM kernels run about twice as fast at the same units), taken at 1800 MHz in the same run as the others.
- g_bgalone_3bpsm: the bg kernel alone at 3 blocks per SM, instrumented, for its G_thr and gate.
- Concurrency rule, fixed now: if P6 fails in the main cells, concurrency (different-context work overlapping in time) is reported as a FINDING only if overlaps by the same OVERLAP definition (more than 10 us, trusted blocks, recorded interval) also appear in g_T4_3bpsm (at least one, as P6 itself is judged). If P6 fails in the main cells but g_T4_3bpsm shows none, the main-cell overlaps are reported as unexplained and NOT as concurrency. If g_T4_3bpsm shows overlaps, same-SM and different-SM counts are reported separately. The control has no alone cell, so q and s are not computed for it.

## D. Open observation (not in scope)
In the plain single-context kernel, blocks 4-6 per SM stall about 267 us while blocks 1-3 run (warp-scheduler arbitration, probably older-warp priority with 48 warps competing for issue). Per-block service time is therefore not uniform within a kernel. A later Nsight Compute warp-state check could confirm the mechanism.
