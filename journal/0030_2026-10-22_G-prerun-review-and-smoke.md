## The finding that changes the plan: gaps do not mean suspension at block level
The smoke report looked wrong (28,275 "overlaps", q 0.385 ms, s 0.10 ms, 308 negative-s transitions) so I looked at the raw intervals instead of trusting the registered definitions.
- In g_T4_alone (no other process) blocks 0-107 of every request run gap-free; blocks 108-215 show gaps of 240-400 us. In g_bgalone, 132,192 of 264,384 recorded bg blocks (exactly 50.0%) have a gap >= G_thr (median 267 us). Review finding 6 expected this to be other GPU contexts; it is not.
- Controlled probe (bg alone, 1.5 s each, instrumented kernel): blocks per SM 1, 2, 3 -> 0.000 of blocks with a gap >= G_thr; 4 -> 0.250; 5 -> 0.400; 6 -> 0.500. The share equals (n - 3) / n: the blocks beyond the first three per SM are starved by the SM's warp arbitration while earlier blocks run. Not tested why (age-ordered issue priority is a candidate).
- So a gap in a block with blockIdx >= 108 is not evidence of a context switch. The union-level launch on-set (runs) is robust to this (some witness block is always running), but block-level overlap (P6), the preempted fraction (P7) and G_thr built from bgalone are not. Restricting those to the witness blocks (blockIdx < 108): bgalone shows 0 gaps in 132,192 witness blocks. Contended cells then show preempted bg fractions 10-19%, q about 0.375 ms, s about 0.13 ms with 139 negative-s transitions of 3,498 and fg/bg on-intervals that still overlap (g_T4: 5,230 of 43,200 witness fg blocks, 21% on the same SM, median overlap in the unrestricted data 372 us). Smoke-grade; nothing here is a prediction outcome. If it repeats on locked-clock data, P4, P5 and P6 do not hold as written; what that means is for the reviewer.
- Proposed (draft addendum 3, committed as _DRAFT, NOT REGISTERED): witness blocks for all block-level analyses, an instrument validity gate (bgalone witness preempted fraction < 1%), all-blocks view as labelled secondary. The analysis supports both (`w2_g_analysis.py` default witness, `--all-blocks`).
